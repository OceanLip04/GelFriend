# 胶个朋友 · 软件逻辑复审

日期：2026-10-15。审查对象：2.2.2 源码。

本轮为产品和代码审查，没有修改应用逻辑或重新发布安装包。以下明确区分组件复现、静态代码发现与产品建议；组件使用合成数据和模拟 Canvas，不代表真实胶图识别质量或原生操作验收。

## 结论

实验类型入口、大图查看、常驻泳道切换、手工三框泳道和显式 Marker 配对应保留。下一轮优先统一对象身份、结果依赖和项目生命周期，再修正导航。界面应表达同一套可靠状态，避免继续用独立按钮事件补流程。

## 一、优先修复的数据和项目问题

### 1. 删除对象后不能继承旧引用（最高优先）

组件复现：L1 的 b1 对应 500 bp；删除 b1 后在另一位置新增条带，新条带再次获得 b1，旧的 500 bp 对应仍指向 b1。此时重新标定可能把新条带视为旧标准点；是否会被顺序等数值检查拦住取决于新位置，不能依赖后续算法拦截。

原因：app.js 的 nextID 使用首个空缺编号；profile-editor.js 删除条带不清除或标记相关 Marker 引用。泳道删除、整批重建和自动重新检测也必须审查同类引用问题。

建议：对象内部使用不可复用 ID，L1/b1 只是显示标签。删除后，Marker/量标准/Western 引用明确成为“原条带已删除，需重新选择”，不能自动指向新对象。重新识别生成候选对象，对应关系需重新核对，不按顺序沿用。

验收：配对→删除→新增→保存重开→重新识别，新对象始终不自动继承旧标准或样本关系。

### 2. 编辑中的标准与已应用结果必须区分（最高优先）

组件复现：已知量标定完成后，把编辑框的 10 改为 30，amountPairs 已为 30，quantitySpec 仍为 10，calibrationDirty.quantity 为 false。输入和结果来自不同版本，界面没有说明。

建议：标准、方法、单位采用草稿/已应用版本；任何相关编辑立即显示“有修改，尚未应用”。主按钮为“更新定量结果”。导出使用明确的已应用版本，未应用草稿不能混入正式有效结果。删除量标准、修改拟合方法、关闭/重开页面都遵循此规则。

### 3. 量标准必须绑定通道

组件复现：demo0 设置的 amountPairs 只含泳道/条带编号，切到 demo1 后再次计算会直接用相同编号套用到新通道，没有转移确认。新通道可能有这些编号，但不意味着用户选择过这些量标准。

建议：量标准及参考条带完整绑定图像、通道、泳道、条带。各通道保留自己的标准配置；跨通道复制是显式操作，先预览、再核对。当前 mwSpec/quantitySpec 单套对象也应改为按通道存储，避免通道 A 与 B 的标定互相覆盖。

### 4. 项目保存和离开需要完整闭环

静态发现：App.swift 的 applicationShouldTerminate 仅检查批量运行，其他情况直接退出；AnalysisWindow 没有未保存关闭检查。导入新图/新项目会替换工作状态；saveText 每次弹保存框，没有已保存位置与修订号的闭环。

建议：维护项目名称、保存路径、修改版本、保存版本、恢复副本。Cmd+S 更新原项目，“另存为”保存副本。关闭、退出、替换项目统一检查未保存修改，提供保存/不保存/取消；自动恢复覆盖异常退出。普通换步骤、关参数、回首页保留当前项目，不反复询问。

## 二、让流程和返回符合用户意图

### 5. 页面切换不能冒充数据修改

组件复现：已确认泳道后只返回泳道页，laneSetupConfirmed 变为 false，但 workflowDone 仍含 lanes，canEnterStep('bands') 又返回 true。界面同时存在“未确认”和“已完成”两种判断。

建议：查看步骤不修改确认状态；只有实际改变泳道几何、删除/新增对象或改变角色时，按依赖标记相关内容待核对。步骤状态由数据版本推导，不分别维护互相矛盾的布尔值和完成清单。

### 6. 可选步骤要在前进和返回中都可跳过

组件复现：无 Marker 的项目能从条带直接进入结果，但结果页“上一步”按固定步骤数组返回 Marker；Marker 数量为 0，下一步按钮禁用。

静态发现：定量比较只有“计算已知量”主按钮；仅选择相对参考再点击它，会被要求添加独立量标准。错误提示让用户另找“返回结果”，动线不完整。

建议：根据当前任务生成有效步骤。无 Marker 时，结果的上一步直接回核对条带；允许稍后明确添加 Marker。定量入口先选“相对比较”或“已知量标定”，分别显示“应用比较”和“计算/更新定量”，不要求相对比较输入绝对数量。

推荐默认路线：

选择实验 → 打开图像 → 大图查看 → 设置泳道 → 核对条带 →〔需要大小时核对 Marker〕→ 结果 → 保存/导出。

相对比较、已知量标定属于结果页的可选任务。Western 使用自己的目标/参照与归一化步骤。菌落与斑点保留已有独立路线。

### 7. 结果状态应细到通道/泳道/条带

组件复现：只修改样本 L2 的 b2 边界，未动 L1 的 Marker，现有 invalidateCalibrations 仍使所有大小标定待更新。

建议明确依赖：

| 修改 | 应更新的内容 |
| --- | --- |
| 旋转、反相、倍率、平移 | 显示状态；不使科学结果失效 |
| 一个普通样本条带边界 | 该条带积分、大小与相关比较结果；保留不依赖它的标准模型 |
| Marker 标准点/标准泳道几何 | 该 Marker 模型及实际依赖它的样本结果 |
| 已知量标准的值或积分 | 对应量模型及相关数量结果 |
| 某个 Western 目标/参照或参考样本 | 对应归一化结果及依赖的相对倍数 |
| 背景/信号设置 | 实际受影响的通道和计算结果 |

结果旁显示具体原因与定位入口，如“L1 的 500 bp 标准带已删除 → 重新对应”。已识别候选、人工已改和用户已核对是不同状态；手工编辑不自动代表已完成核对。

## 三、跨页面体验保持连续

### 8. 全局观察状态尚未完全统一

组件复现：预览页开启反相，进入分析后 viewerInvert=true，但 invertPreview=false。workflow.js 捕获“开始分析”事件后没有执行 viewer.js 原来的反相复制逻辑。

静态发现：预览黑白点、Gamma 与分析显示采用不同入口；项目 settings 不保存预览显示控件。批量设置读取旧原生查看窗口的 lowSlider/gammaSlider/angle，而非当前 Web 工作区。

建议：每个通道只有一份观察设置，查看、框泳道、核对、结果共用并保存。批量“沿用当前图像设置”从同一状态获取，运行前预览代表图。原始 TIFF 明确保持原始像素与方向；显示调整导出另列 PNG，避免用户把两者理解为相同处理。

### 9. 撤销不应因切换泳道消失

静态发现：profile-editor.js 在泳道或通道改变时清空曲线撤销栈；泳道框调整另用 laneEditHistory；未形成统一重做。

建议：项目级编辑历史统一处理泳道、条带、配对和标准编辑，提供 Cmd+Z/Shift+Cmd+Z，明确“撤销删除 L2 的条带”。换泳道或换步骤不会丢历史。识别批量替换是一条可撤销操作；显示操作不挤占数据撤销记录。

### 10. 导出前增加简洁核对页

静态发现：结果页“导出结果”直接调用报告；状态字段主要围绕 calibrationDirty，尚未统一草稿、逐对象核对和缺失引用状态。

建议：导出面板默认显示当前实验、图像/通道和样本范围、有效/待核对/待更新数量；点击问题可定位。提供“当前视图/完整标注图”“简洁结果”“完整报告”“可继续编辑项目”。允许导出未完成内容时清楚标为草稿，并逐行带原因，不能混为正常有效数值。避免再加入占用大胶图空间的常驻清单。

## 实施顺序

1. 不可复用对象 ID、引用完整性、量标准草稿与通道绑定、未保存与恢复机制。
2. 统一步骤状态、无 Marker 返回、相对比较出口、按依赖更新结果。
3. 统一跨页显示设置及批量桥接、项目级撤销重做、导出核对。
4. 针对真实胶图做查看→手工泳道→删空泳道→多 Marker→缺带配对→修改→导出→重开完整验收，再打磨状态反馈与动效。

图像仍占最大空间；问题清单、标准编辑、结果汇总通过按需面板呈现。常驻只保留当前步骤、当前通道/泳道、观察与编辑工具、主操作。已有独立专注模式、全局旋转圆环和底部可调曲线继续保留。

本轮执行了 7 个针对性的组件复现场景：泳道确认矛盾、无 Marker 返回、量标准草稿未失效、样本编辑连带失效、反相跨页不一致、已删除条带 ID 复用、量标准跨通道复用。其他条目依据静态代码审查提出，尚未作为修复交付。
